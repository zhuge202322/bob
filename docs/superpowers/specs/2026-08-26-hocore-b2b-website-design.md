# Hocore Biotech B2B 企业官网设计规格

日期：2026-08-26  
状态：待用户最终审阅  
项目：深圳泽鸿衍生物科技有限公司（Hocore Biotech）生物科研试剂与实验室耗材 B2B 官网

## 1. 项目目标

建设一套面向俄罗斯科研采购市场的三语 B2B 企业官网，展示 Hocore Biotech 的全球品牌寻源、集中采购、批次追溯、温控运输和中俄合规交付能力。

网站不是公开定价商城。首期采用“产品品类目录 + 采购服务 + 权威资源 + 即时咨询 + 专业询盘”的模式，帮助科研机构、检测机构、生物医药企业和区域经销商完成以下任务：

1. 快速确认可供应的试剂、耗材品类与代表品牌。
2. 通过品牌、CAT No.、规格或应用描述发起寻源。
3. 通过 WhatsApp 或 VK 进行即时咨询。
4. 通过独立 RFQ 页面提交结构化询盘和采购清单附件。
5. 查阅溯源、COA/TDS/SDS、温控和跨境合规资料，形成采购信任。

## 2. 已确认的业务约束

- 默认语言：英文。
- 可切换语言：中文、俄语。
- 主转化入口：WhatsApp、VK 即时咨询。
- 专业转化入口：独立 RFQ 询盘页。
- 产品展示方式：品类目录型，不公开价格，不建设购物车与在线支付。
- 首期内容：产品目录、采购服务、质量与合规、资源中心、公司信息、联系方式和询盘。
- 技术路线：Next.js + SQLite + 自主开发管理后台。
- 后台必须支持产品类目、产品、客服联系方式、公司 Logo、网站名称、所有页面板块图片和社媒链接的新增、修改与删除。

## 3. 资料提炼与品牌定位

### 3.1 企业定位

Hocore Biotech 是面向俄罗斯市场的生命科学产品跨境采购与交付伙伴。核心价值不是单一品牌代理，而是覆盖美洲、欧洲、亚太和中国的多渠道供应网络，以及中俄专线、温控运输、文件配套和合规清关能力。

建议英文核心定位：

> Global life science sourcing and compliant delivery for research teams across Russia.

建议中文核心定位：

> 面向俄罗斯科研团队的全球生命科学产品寻源与合规交付服务。

### 3.2 目标客户

- 科研院所与高校实验室。
- 生物医药企业与工业研发部门。
- 临床检验和第三方检测机构。
- 俄罗斯区域经销商与采购服务商。
- 大客户招标、项目型采购和长期框架协议客户。

### 3.3 核心信任证据

- 全球品牌与多区域供应渠道。
- 原厂或授权分销渠道来源。
- 原厂包装、批号、COA、TDS、SDS 和对应技术文件。
- 无菌、无酶、无热源产品的相关说明。
- 常温、2-8°C、-20°C 分温区运输与温度记录。
- 欧亚监管场景下的申报文件与合规清关支持。
- 常规现货送达俄罗斯主要城市的参考周期为 15-25 天。
- 指定型号接单后 3 个工作日内反馈货期与报价。

页面只能呈现真实、可验证的信息。不得虚构认证证书、客户 Logo、合作案例、团队规模、仓库规模或服务数字。

## 5. 页面规划

### 5.1 首页

首页按下列顺序组织：

1. 全宽 Hero 轮播。
2. 试剂、耗材、指定寻源三个快速入口。
3. 产品矩阵概览，共 16 个核心品类。
4. 全球供应网络与代表品牌产区。
5. 采购服务：集中采购、指定寻源、替代选型、经销合作。
6. 质量与合规：溯源、技术文件、温控、清关交付。
7. 关键交付指标：15-25 天、3 个工作日、三档温区。
8. 资源中心精选内容。
9. 终端客户与经销商两类合作模式。
10. RFQ 行动区和联系方式。

Hero 使用 3 张全宽真实场景大图：

- 全球生命科学产品供货：实验室、试剂和耗材的真实工作场景。
- 冷链交付：保温包装、温度记录或冷链操作场景。
- 简化采购：采购清单、品牌/CAT No. 寻源或产品矩阵场景。

轮播要求：自动轮播、左右箭头、进度指示、键盘操作、暂停控制和减少动画偏好支持。文字区域固定在安全区，图片使用独立桌面/移动端焦点设置，避免人物或产品被裁切。首屏必须保留 Request a Quote 与 Explore Products 两个 CTA。

### 5.2 产品中心

产品中心不是 SKU 商城，而是可搜索的供应能力目录。

入口页展示试剂与耗材两条产品线、16 个核心品类、代表品牌和常见采购方式。筛选条件包括：

- 产品线：Reagents / Consumables。
- 应用方向。
- 品牌与品牌产区。
- 规格关键词。
- 储存温区：Ambient / 2-8°C / -20°C。

每个品类页包含：

- 品类名称和应用简介。
- 产品范围。
- 主力规格。
- 代表品牌，按产区分组。
- 储存/运输属性。
- 对应文件类型说明。
- 相关采购服务。
- 相关资源文章。
- WhatsApp、VK 和预填品类的 RFQ CTA。

每个产品页包含可选字段：产品名称、所属品类、品牌、CAT No.、规格、应用、温区、产品图片、简要描述、文件可用性和询价 CTA。后台可以维护产品，但前台不展示价格、购物车或库存承诺。

### 5.4 采购服务

四个服务页面使用统一结构：客户问题、适用场景、服务流程、所需信息、交付物、常见问题和 CTA。

- 集中采购：统一对接、统一结算、长期框架协议和专属备货。
- 指定型号寻源：按品牌、CAT No. 或完整规格全球寻源。
- 替代选型：针对断供、停产或高成本产品提供可比方案，不做未经验证的性能承诺。
- 经销商合作：阶梯供货、试采、一件代发、项目协同和资料支持。

### 5.5 质量与合规

该板块承担网站权威性的主要证据表达，包含：

- 原厂与授权渠道来源说明。
- 批次、COA、TDS、SDS 和质量文件说明。
- 常温、2-8°C、-20°C 分温区运输流程。
- 温度记录与到货文件。
- 欧亚场景的申报、清关和交付节点。
- 采购、质检、包装、出口、清关、交付的流程图。

合规页面必须包含科研用途声明：试剂仅供科研使用，不用于临床诊断或治疗。品牌仅用于代表性供应能力展示，规格、价格、周期和服务条款以最终合同为准。

### 5.6 资源中心

资源内容分为四类：

- Procurement Guides：品牌/CAT No. 询价、采购清单准备、替代选型。
- Storage & Shipping：常温、冷藏、冷冻运输和收货检查。
- Quality Documents：COA、TDS、SDS、无菌/无酶/无热源文件说明。
- Compliance & FAQ：清关、交付周期、科研用途和常见问题。

文章页包含标题、摘要、正文、主题、发布日期、最后更新时间、审核人/部门、相关产品、相关服务、相关下载和 RFQ CTA。只有存在真实审核人员信息时才展示姓名，否则使用“Hocore Technical & Supply Team”等部门署名。

### 5.7 RFQ 询盘页

表单字段：

- 客户类型：终端客户 / 经销商 / 其他。
- 公司名称。
- 联系人。
- 工作邮箱。
- 电话、WhatsApp 或 VK 联系方式。
- 所在国家与交付城市。
- 品牌。
- CAT No.
- 产品名称或规格描述。
- 数量。
- 储存温区。
- 期望交付日期。
- 补充说明。
- 采购清单附件。
- 隐私政策同意。

允许 PDF、XLSX、XLS、CSV、DOCX，单文件大小上限默认 10 MB，可在配置中调整。上传文件保存到私有目录或兼容 S3 的对象存储，不能通过猜测 URL 公开访问；后台通过鉴权接口下载。

提交后生成询盘编号，显示成功页，并向商务邮箱发送通知。后台状态：New、In Review、Quoted、Won、Lost、Spam。后台支持内部备注、附件下载、CSV 导出和状态筛选。

## 7. 技术架构

### 7.1 应用结构

- Next.js App Router + TypeScript。
- 前台与 `/admin` 自研后台位于同一代码库。
- SQLite 作为内容和业务数据数据库。
- ORM 建议使用 Prisma，统一迁移、类型和事务管理。
- 服务端渲染和增量缓存用于公开内容页面。
- 后台和询盘接口使用服务端 Route Handlers 或 Server Actions。
- 图片使用 Next.js Image 处理，上传时生成必要尺寸并记录宽高、格式和 Alt 文本。

### 7.2 部署约束

SQLite 要求单实例写入和持久磁盘，因此生产环境采用单台 VPS 或单实例 Docker 部署。不得部署为无状态 Serverless，也不得在没有共享锁机制的情况下横向扩容多个写入节点。

建议生产拓扑：

```text
Reverse Proxy / TLS
        |
Next.js single instance
   |             |
SQLite WAL     Private uploads / S3-compatible storage
   |
Scheduled backup -> remote backup location
```

启用 SQLite WAL 模式、合理 busy timeout 和短事务。数据库与本地附件目录必须挂载持久卷。每日自动备份，保留至少 7 个日备份和 4 个周备份，并定期验证恢复。

### 7.3 缓存与发布

公开页面读取已发布内容。后台保存草稿后不立即影响前台；发布时更新 `publishedAt` 并触发对应路径缓存失效。站点设置、导航和联系方式变更触发全局布局缓存失效。

## 8. 数据模型

### 8.1 核心实体

- `User`：管理员、编辑员角色，密码哈希、状态和最后登录时间。
- `SiteSetting`：网站名称、默认语言、启用语言、Logo、Favicon、默认 SEO、页脚声明。
- `Contact`：类型、标签、值、链接、排序、启用状态。
- `SocialLink`：平台、URL、图标、排序、启用状态。
- `Page`：页面键、路径、发布状态、SEO 与三语元数据。
- `PageSection`：页面、板块类型、排序、显隐、三语标题/正文/CTA、图片引用和展示配置。
- `HeroSlide`：三语标题/正文/CTA、桌面图、移动图、图片焦点、排序、启用状态。
- `ProductLine`：试剂或耗材。
- `ProductCategory`：产品线、三语名称/描述、规格、品牌、温区、图片、排序和 SEO。
- `Product`：品类、品牌、CAT No.、规格、应用、温区、图片、文件可用性、三语描述、发布状态。
- `Brand`：名称、产区、官网链接和启用状态。
- `Article`：栏目、三语标题/摘要/正文、封面、作者/审核、发布时间、SEO。
- `Faq`：三语问题/回答、主题、排序、启用状态。
- `MediaAsset`：文件名、存储键、MIME、大小、宽高、Alt 文本、哈希和上传人。
- `Rfq`：客户信息、采购信息、来源页面、状态、时间和同意记录。
- `RfqAttachment`：询盘、私有存储键、原始文件名、MIME、大小和哈希。
- `AuditLog`：用户、操作、实体、实体 ID、变更摘要、IP 和时间。

### 8.2 三语字段策略

可翻译内容使用独立翻译表，例如 `ProductCategoryTranslation`、`PageSectionTranslation`、`ArticleTranslation`，字段包含 `locale`、标题、摘要、正文、slug 和 SEO。不可翻译字段如 CAT No.、规格数值、温区、排序和状态只存一份。

数据库对 `(entityId, locale)` 建唯一索引，对每种语言的 slug 建唯一索引。后台显示每种语言的完成状态，英文为必填发布语言；中文与俄语可保存草稿，但若对应语言页面未完成，则不进入该语言站点导航。

### 8.3 删除规则

- 默认使用软删除，保留 `deletedAt` 和审计记录。
- 被页面或产品引用的图片禁止直接物理删除。
- 含产品的品类禁止直接删除，必须先迁移产品或停用品类。
- 站点唯一设置、最后一个管理员账户不可删除。
- RFQ 和审计记录只允许归档，不允许普通编辑员删除。

## 9. 自研后台

### 9.1 模块

- Dashboard：内容数量、草稿、最新询盘、最近操作。
- Site Settings：网站名称、Logo、语言、SEO、页脚声明。
- Pages & Sections：页面板块的增删改、排序、显隐、图片和三语内容。
- Hero Slides：轮播图、移动图、焦点、CTA、排序和状态。
- Product Categories：品类 CRUD 与排序。
- Products：产品 CRUD、筛选、批量状态修改。
- Brands：品牌与产区维护。
- Contacts & Socials：客服、WhatsApp、VK、邮箱、地址和工作时间。
- Resources：文章、FAQ 和下载资料。
- Media Library：上传、搜索、替换、引用检查与安全删除。
- RFQ Inbox：询盘状态、附件、备注、导出。
- Users & Audit Log：账号、角色和操作记录。

### 9.2 编辑体验

- 草稿、预览、发布三段式流程。
- 三语标签页和翻译完成提示。
- 页面板块支持拖动排序，但板块类型来自受控组件库，避免任意 HTML 破坏版式。
- 图片上传前显示尺寸和文件大小，要求填写 Alt 文本。
- 保存前校验必填项、URL、电话格式、文件类型和 slug 冲突。
- 删除前显示引用影响，重要操作二次确认。

### 9.3 权限

- Admin：全权限、用户管理、设置、发布和导出。
- Editor：内容、产品、图片和 FAQ 编辑，可预览；是否可发布由管理员配置。
- RFQ Operator：只读内容，可处理询盘和下载询盘附件。

## 10. SEO 与多语言

- 每个语言版本拥有独立 title、description、slug、Open Graph 图片和 canonical。
- 输出 `hreflang`：`en`、`zh-CN`、`ru-RU` 和 `x-default`。
- 自动生成 sitemap.xml 和 robots.txt。
- 产品类目、文章、FAQ 使用适当的结构化数据；不使用 Product 价格结构化数据。
- 后台提供重定向记录，修改已发布 slug 时自动创建 301 重定向。
- 搜索页与组合筛选页默认 `noindex`，避免重复内容。
- 图片文件名、Alt 文本和标题按语言管理。

## 11. 安全与隐私

- 后台密码使用 Argon2id 或 bcrypt 高成本哈希。
- 会话 Cookie 使用 HttpOnly、Secure、SameSite=Lax/Strict。
- 登录、RFQ 和上传接口实施速率限制。
- 表单使用 CSRF 防护、服务器端校验和蜜罐字段；必要时接入验证码。
- 富文本使用白名单清洗，不允许任意脚本或内联事件。
- 上传校验扩展名、MIME、文件头和大小；文件名随机化。
- 询盘附件私有保存，通过鉴权下载。
- 后台操作写入审计日志。
- 隐私政策说明询盘数据用途、保存周期和联系方式。

## 12. 错误与状态处理

- 空目录显示业务友好的无结果状态和清除筛选入口。
- 未翻译内容不混用其他语言正文；显示语言级回退提示。
- 图片缺失使用统一科研产品占位图，并在后台提示内容不完整。
- RFQ 提交采用幂等键，防止重复提交。
- 邮件通知失败不回滚已保存询盘；后台标记通知状态并支持重试。
- 数据库不可写或磁盘不足时阻止上传和发布，记录错误并向管理员告警。
- 自定义 404、500 和维护页面都保留联系方式。

## 13. 性能与可访问性

- Core Web Vitals 目标：LCP < 2.5s、CLS < 0.1、INP < 200ms（以主要目标网络环境的第 75 百分位为准）。
- Hero 首张图优先加载，其余轮播图延迟加载。
- 上传图片转为 WebP/AVIF 衍生图，同时保留必要原图。
- 所有交互支持键盘，焦点样式清晰。
- 对比度满足 WCAG 2.2 AA。
- 轮播提供暂停并尊重 `prefers-reduced-motion`。
- 表单错误与成功状态可被屏幕阅读器识别。

## 14. 测试计划

- 单元测试：翻译回退、slug、权限、删除约束、RFQ 校验和文件校验。
- 集成测试：后台 CRUD、草稿发布、缓存失效、询盘保存、附件鉴权下载、邮件失败重试。
- E2E：三语切换、产品筛选、Hero 轮播、WhatsApp/VK 链接、RFQ 提交、后台内容发布。
- 视觉回归：桌面、平板、360 px 移动端；英文、中文、俄语长文案。
- 安全测试：未授权后台访问、越权、CSRF、XSS、上传伪装文件、暴力登录和附件直链。
- 恢复演练：从 SQLite 与附件备份恢复到干净环境。

- 英文为默认语言，中文和俄语可在相同页面上下文中切换。

- 16 个核心品类可从后台维护并在前台正确分类展示。

- RFQ 支持字段校验、附件上传、成功编号、后台状态管理和导出。

- SEO、hreflang、sitemap、canonical 和结构化数据正确。

- 与供应商品牌 ERP 的实时接口。
- 客户账户、合同和账单门户。
- 自动机器翻译直接发布。
- 多节点水平扩容和高并发写入架构。
